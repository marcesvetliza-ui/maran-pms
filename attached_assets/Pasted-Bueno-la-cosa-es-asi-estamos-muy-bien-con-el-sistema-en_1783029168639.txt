Gestión de Compras y Carga de Facturas

Se discutió la necesidad de que Julián cambie su metodología de trabajo; debe cargar la factura completa (artículos, costos y cantidades) en lugar de solo conceptos, para que el sistema refleje el stock real y los costos precisos.

Aylin se encarga actualmente de cargar las facturas que no son de mercadería directa, como los servicios o compras de housekeeping, mientras que Ana controla las cantidades.

El objetivo es que la carga de artículos dispare automáticamente los asientos contables, evitando que administración tenga que intervenir en la transcripción de datos operativos básicos.

Estructura Contable y Configuración de Asientos

Speaker 3 recomendó asignar una cuenta contable de compra y otra de venta a cada producto individual para ganar flexibilidad, criticando la rigidez de otros sistemas web que agrupan demasiado los conceptos.

Es fundamental definir la configuración de los asientos para que cada comprobante (facturas, notas de débito y crédito) dispare el movimiento correcto en el debe y el haber, incluyendo las distintas alícuotas de IVA (10.5%, 21%, 27%).

Se identificó la falta de un módulo para "asientos manuales" que permita registrar movimientos que no provienen de facturas, como transferencias bancarias, depósitos o salidas de caja menores.

Speaker 1 verificará si el plan de cuentas cargado coincide exactamente con el que utiliza actualmente la contadora para asegurar una transición fluida.

Operatividad en Restaurante y Cocina

Se propuso simplificar el menú eliminando opciones que no son útiles para los mozos y unificando las secciones de "Receta" y "Costos" en una sola vista para Diego (cocina) y Gonzalo (restaurante).

La idea es automatizar la asignación contable mediante categorías: si un plato se marca como "Entrada" o "Principal", el sistema ya sabe internamente que debe ir a la cuenta de "Comestibles" sin que el usuario lo seleccione manualmente.

Se discutió la posibilidad de triplicar artículos (como el agua mineral) si se venden en diferentes puntos como el Spa, el Hotel o el Restaurante, siguiendo la lógica de sistemas como Pecson, aunque esto depende de cómo se gestionen los depósitos.

Decisiones sobre el Lanzamiento y Cierre

Se planteó la posibilidad de lanzar el sistema centrándose primero en la parte operativa y de ventas, dejando la automatización contable total para una segunda etapa, dado que muchos hoteles operan entregando listados de ventas a contadores externos.

Se acordó que hay un margen de tiempo (hasta el próximo ejercicio contable) para terminar de pulir el módulo de contabilidad detallada.

La próxima semana se realizarán pruebas físicas con las impresoras y comanderas para asegurar que el flujo desde el pedido hasta la impresión del ticket funcione correctamente.
