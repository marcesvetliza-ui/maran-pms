## Problem
The build fails during `npm ci` with `npm error Exit handler never called!` after hanging for ~4 minutes, indicating an npm OOM crash. The service uses Railpack (auto-detected Node.js, npm package manager). The build stage fails with exit code 1:

```
npm error Exit handler never called!
npm error This is an error with npm itself.
Build Failed: build daemon returned an error < failed to solve: process "npm ci" did not complete successfully: exit code: 1 >
```

The Railpack version upgraded from 0.29.0 (last successful build, commit 545952a5) to 0.30.0 (current failing builds), invalidating cached node_modules layers. No railway.json or railway.toml config file is present — all settings are auto-detected. The package-lock.json is 416KB.

## Diagnosis
Two compounding issues cause the failure:
1. The package-lock.json contains resolved URLs pointing to Replit's internal package proxy (`package-firewall.replit.local`) for recently added packages (`bcryptjs`, `@types/bcryptjs`). These URLs are unreachable from Railway's build environment, causing npm to hang on network timeouts before eventually crashing.
2. The large dependency tree (416KB lockfile), combined with the Railpack cache invalidation (0.29.0 → 0.30.0), requires a full cold install that exceeds available build memory.

The previous successful build used cached layers so npm ci was effectively a no-op and completed in ~1.5 minutes. Without cache, the combination of unreachable registry URLs and the large dependency tree causes npm to OOM after ~4 minutes.

The `nixpacks.toml` file added in this commit (phases.install, phases.build, start cmd) is irrelevant — Railway uses Railpack, not Nixpacks, so this file is silently ignored.

## Fix
1. **File: `package-lock.json`** — Must be regenerated outside of Replit by running `npm install --registry https://registry.npmjs.org/` on a local machine (not in Replit). This replaces all `package-firewall.replit.local` resolved URLs with public `registry.npmjs.org` URLs. Commit the updated lockfile. This step cannot be automated by a code agent as it requires running npm commands to regenerate the lockfile.

2. **File: `nixpacks.toml`** — Delete this file entirely from the repo root. It has no effect on Railway (which uses Railpack, not Nixpacks) and its presence is misleading.
